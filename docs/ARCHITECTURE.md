# Архітектура

## Пайплайн

```text
текст → препроцес → вербалізація (Gemma-3-270M ONNX int8 або rule)
      → стрес (словник marisa-trie → accentor-фолбек для OOV)
      → фонемізація (ipa_uk) → токенізація → генерація (ONNX/ORT) → PCM/WAV

клон: WAV → 24 кГц resample → voice encoder (ONNX int8) → speakers/<назва>.npy
      → синтез за іменем голосу (пресети та клони в одному просторі ембеддінгів)
```

Ядро — C++20-бібліотека (`src/core`), сервер — Drogon (`server/`), інференс — ONNX
Runtime. Python у рантаймі не використовується: він потрібен лише для завантаження
моделей і службових скриптів.

## Стрес

**Словниковий + neural фолбек.** `stress.trie` (marisa-trie, 2.9 млн ключів) покриває
більшість форм за мікросекунди. Слова поза словником обробляє **accentor-lite** — LSTM,
експортований в ONNX (single-file, ~1.2 МБ), той самий `ukrainian_accentor`, що й у
Python-конвеєрі. Unicode-регістр нормалізується utf8proc (паритет з Python
`word.lower()/title()`).

## Вербалізація

Два режими (`auto_verbalize`):

| Режим | Реалізація | Латентність | Якість |
|---|---|---|---|
| `neural` (типово) | Gemma-3-270M (український verbalizer), ONNX int8, KV-cache | ~1–3 с на речення (CPU) | дослівний паритет з hybrid (4/4 MATCH) |
| `rule` | C++ регулярки (цифри/дати/час) | мілісекунди | базовий (граматика відмінювання гірша) |
| `off` / `false` | текст як є | 0 | — |

Neural-вербалізація вмикається лише для текстів із цифрами (гейт `has_digits`);
без цифр `neural` еквівалентний `rule`. Це зменшує затримку на звичайному тексті.

## Клонування голосу

Voice encoder (StyleEncoder з HolosTTS, експорт в ONNX int8) перетворює WAV 24 кГц у
256-вимірний ембеддінг. Ембеддінг зберігається як `speakers/<name>.npy` (numpy
`float32[256]`) і далі використовується генератором нарівні з пресетами. Формат
сумісний з HolosTTS-hybrid.

Енкодер створює ORT-сесію ліниво (при першому енролменті), під час кодування пік RSS
зростає на ~0.85 ГБ, після — звільняється (арена ORT вимкнена). Одночасні енролменти
серіалізуються. Деталі API та ліміти — [API.md](API.md#клонування-голосу).

## Паритет з hybrid

Схема запитів/відповідей і тривалість аудіо збігаються з
[HolosTTS-hybrid](https://github.com/Karnemorkon/HolosTTS-hybrid) у межах Δ ≤0.02 с;
neural-вербалізація дослівно збігається на тестових фразах. Вимірювання й відомі
відмінності — [BENCHMARKS.md](BENCHMARKS.md#паритет-з-hybrid).

## Структура репозиторію

```text
src/core/      бібліотека ядра (текст, вербалізація, стрес, фонеми, ONNX, аудіо)
src/cli/       holos-cli
server/        Drogon HTTP/WS (:8004)
scripts/       download_models.py (HF → models/), бенчмарки
tools/         допоміжні скрипти (конвертація int8, паритет PCM, експорт енкодера)
tests/         unit + golden-тести
cmake/         FetchContent-залежності
docker/        multi-stage Dockerfile
desktop/       Tauri-лаунчер для портативних збірок
packaging/     AppImage/NSIS-пакування
```

## Рішення

- **Один бінарник + ORT** замість Python-стеку: менший образ, немає GIL і залежності від
  PyTorch у рантаймі.
- **INT8 ONNX** для генератора й енкодера: CPU-інференс без GPU.
- **Словник + accentor**: швидкий детермінований шлях для більшості слів, neural — лише
  для OOV.
- **Multi-arch** збірка нативними runners (amd64 + arm64) без QEMU; ARM64-образ проходить
  runtime-смоук до публікації маніфесту.
